## Read this first: behaviour changes

Four things change what an existing consumer observes. None removes data, and
no `INC-*` ID is removed.

### 1. `load_deprecations()` returns different values for 5 keys (Python API)

Compared with the v2.12.0 package, `genai_incidents.load_deprecations()` returns
a different value for **5 of its 293 keys** (293 keys in both releases). Re-derived
by loading both packages side by side (the recipe is in Verification):

| Key | v2.12.0 | v2.13.0 | Change |
|---|---|---|---|
| `INC-00311` | list of 12 IDs | `"INC-14726"` | **shape**: list to str (D72, from D69) |
| `INC-01897` | list of 8 IDs | `"INC-14612"` | **shape**: list to str (D72, from D69) |
| `INC-00497` | `"INC-00311"` | list of 12 IDs | **shape**: str to list (D72) |
| `INC-03128` | `"INC-00754"` | `"INC-14909"` | **value**, same shape (silent-IDs work) |
| `INC-08185` | `"INC-08139"` | `"INC-14742"` | **value**, same shape (silent-IDs work) |

The documented return type is already `dict[str, str | list[str]]`, but code
that assumed `INC-00311` or `INC-01897` is always a list, or `INC-00497` always
a string, will break. **Use `resolve_id()`, `resolve_id_group()` or the new
`resolve_id_status()` instead of indexing the mapping**; their answers for
the 1,065 distinct `from` IDs, and for every ID that was live in any release,
are the same as before except where this section and the silent-IDs entry below
say otherwise. Why `INC-00497` flips: it used to reach its 12 successors
*through* `INC-00311`; once `INC-00311` was narrowed to one identified
incident (D69), `INC-00497` needed its own list so that it would not silently
move to an incident it never named. The same list is in `CHANGELOG.md`
[Unreleased], under "Behaviour changes".

### 2. `updated`, STIX `modified` and the MISP timestamp now move on more fields (D73, as ruled in D81/D82)

`tier`, `quality_tier`, `corpus` and `content_license` are now **content
fields**. From now on a licence relabel or a classifier change on a row moves
that row's `updated`, and with it its STIX `modified` and its MISP event
timestamp. A consumer that dedupes or syncs on those stamps will now see these
changes; before, they were invisible to it. This matters most for the 3,767
rows that carry `content_license` today (CVE-TOU 2,171, AIAAIC 1,517,
AVID 79). `source_freshness` stays outside the set.

- **This release itself:** a rebuild on the first day after this change moved
  0 rows for this reason (measured against `main` by the gate). The `updated`
  moves in the data are all from the ATLAS and dispute changes below (5,860
  rows, re-derived against the v2.12.0 tag).
- **Freeze widening (D82):** the OECD/AIID stage-1 freeze also holds `tier`,
  `quality_tier` and `corpus` changes on published OECD/AIID rows, because they
  are now content fields.
- **STIX `modified` changes once for every object** in this release (the
  mechanism is in "Export integrity" below). A client that dedupes on
  (`id`, `modified`) will re-import the whole bundle, which is intended.

### 3. The served `data/incidents.core.json` gains `status`

The site's initial-load payload (`docs/data/incidents.core.json`, served from
Pages) now carries `status` on the rows that have one: **22 rows, all
`disputed`** (the 29 retracted rows are not in the payload at all). The
payload grows by **440 bytes** (6,687,566 to 6,688,006). A consumer that
validates that payload against a closed field list will see a new field.

### 4. Two new values consumers may meet

- `status_reason.code` has a second value, `cve-disputed`, and the 22 disputed
  entries carry `status: disputed`. A strict validator built against the
  v2.12.0 schema (enum `["cve-rejected"]`) rejects them; use the v2.13.0
  schema. The new schema rules: `retracted` goes only with `cve-rejected`,
  `disputed` only with `cve-disputed`, and a disputed entry is never
  `confidence: high`.
- `data/id_deprecations.json` gains 24 appended records (1,060 to 1,084; the
  old records are a byte-for-byte prefix) and a new optional field,
  `valid_for_releases`. The file now has a schema,
  `schema/id_deprecations.schema.json`.

## Headline 1 — export integrity (item 8)

- **`SHA256SUMS` now covers the STIX bundle, the TAXII collection and the MISP
  feed.** The Pages workflow used to generate the sums *before* the STIX export,
  so the live `data/SHA256SUMS` listed only `incidents.core.json`,
  `incidents.min.json` and the `detail/` shards and never the bundle. It now
  runs after the exports and writes one `SHA256SUMS` per served tree (`data/`,
  `taxii2/`, `misp/`); the workflow re-verifies each against the built site.
  `scripts/verify_data_integrity.py` also checks every manifest against its
  schema and against `data/stats.json`. Check a download with
  `sha256sum -c SHA256SUMS` inside the directory.
- **STIX `modified` now changes when content changes.** It is the entry's
  `updated` date with the exporter version (currently 1) in the millisecond
  field, never earlier than `created`: an entry with no content change keeps a
  byte-identical object across builds. Before this, `modified` was the bare
  `updated` date, so a change to the exporter (the 2026-10-01 OWASP relabel)
  changed object content without changing `modified`. **Every STIX and TAXII
  object's `modified` moves once in this release** (+1 ms for incidents,
  relationships and CVE objects; the 55 ATLAS `attack-pattern` objects move to
  the 2026-09-15 pin date; the `identity` object to the newest incident date),
  and TAXII `manifest.json` `version` follows.
- **MISP event `timestamp` is derived from the data** (newest `updated` among
  the event's incidents, plus the exporter version in seconds) instead of the
  fixed Jan 1 of the event's year, so a subscribed MISP can now see a content
  change and re-pull.
- **`build_manifest.json` on every channel** (commit, build time, counts copied
  from `data/stats.json`, taxonomy versions): the three Pages trees, the
  Hugging Face dataset, the PyPI package (`genai_incidents.build_manifest()`;
  `None` for an unstamped source checkout) and, new, the GitHub Release, which
  carried no assets before and now attaches the STIX bundle,
  `incidents.min.json`, `taxii2.zip`, `misp-feed.zip`, `build_manifest.json`
  and `SHA256SUMS`.
- **`disputed_count` (22)** is published in `data/stats.json`, the site hero,
  the README, the datasheet and the Hugging Face card; `check_stats_drift.py`
  re-derives all four counts from the corpus and fails on any difference.
- No row in `data/incidents.json` changed for this item. Field-level delta:
  [`docs/audits/ws6-v2130-export-integrity-2026-10-11.md`](https://github.com/emmanuelgjr/genai_incidents/blob/main/docs/audits/ws6-v2130-export-integrity-2026-10-11.md).

## Headline 4 — OECD/AIID: a deliberate freeze, stage 1 (item 7)

- **3,936 OECD-template rows gained two provenance labels:**
  `description_provenance: "original"` and `description_source: "oecd-aim"`

- **Short labels.** The compact label "OWASP ASI" beside the codes in the site

  full framework name is used where the framework is introduced.
- **Not in this release:** the WS3 ID-reuse audit of the 591 multi-title IDs,
  the D66 decouple, the D63 alert, and the rest of the v2.12.0 limitations that

## Verification

Run from a checkout of `main` at `0191e814` (or the `v2.13.0` tag, once cut).
Python 3.12, bash. Scratch copies keep the exporters from writing into the tree.

**Which figures are re-derived after the version bump.** At the cut, the data
version string moves from 2.12.0 to 2.13.0 in the five maintained places and
`make build` rebuilds. **The counts must not move**: 15,666 / 15,637 / 29 / 22 /
1,915 are the same before and after. After the bump, re-run the first block
(it will print `2.13.0`), the drift check and the suite; the `modified` and
`updated` figures, the ATLAS figures and the `load_deprecations` comparison are
properties of the data and need no re-run unless a count moves. If any count
differs after the bump, the cut stops.
