## What is being measured

**Precision** = the share of published rows that are in scope under
[`INCLUSION.md`](../../../../INCLUSION.md) §1: AI-nexus **and**
security/safety relevance **and** evidence. The question comes from board note
N9: the 2026-10-03 wave-1/2 gate measured about 48% (n=40, seed 99) on the
pre-existing CVE/GHSA feed
([`wave12-ingest-gate1-verdict-2026-10-03.md`](../../wave12-ingest-gate1-verdict-2026-10-03.md),
PRECISION section).

## Design

**Frame.** All rows of `data/incidents.json` except `status: retracted`
(29; D44, which excludes them from `incident_count` and from every feed
export). The two frames are partitioned by **`tier`** (`feed` / `landmark`),
the derived field of record (DATA_DICTIONARY.md).

> **Premise correction.** The brief asked for "100 auto + 50 landmark".
> `quality_tier == "auto"` was not used as the first frame because (1) it
> overlaps the landmark set (185 landmark rows are `quality_tier: auto`), so
> the frames would not be disjoint; and (2) most of the N9 population is
> `quality_tier: reviewed`: of the 7968 standing CVE/GHSA feed rows, 5015 are
> `reviewed` (NVD-scored CVEs are labelled `reviewed`). An `auto`-only frame
> would leave most of the rows N9 is about out of the audit. The feed tier is
> the "comprehensive feed" layer of INCLUSION.md §5. `quality_tier` is still
> an implicit stratifier, so per-`quality_tier` figures can be reported.

**Strata.** The explicit strata are tier × source family. Source family is a
fixed priority over `source_ids` prefixes: CVE/GHSA/MAL, then AIID, OECD,
AIAAIC, AVID, arXiv, INC/LEGACY, and then other. A family that holds less
than 2% of its tier is pooled into `<tier>/other`. Implicit stratification:
inside a stratum, rows are sorted by (quality_tier, year, id) and drawn by
seeded systematic sampling, which spreads the draw over quality_tier and year
in proportion.

**Allocation.** Allocation is proportional within each tier, with
largest-remainder rounding. The estimands are tier-level and overall
precision. Proportional allocation keeps each tier's sample self-weighting and
is never less efficient than simple random sampling. Neyman allocation would
need per-stratum variances, and only one is known (CVE/GHSA, n=40). Equal
allocation would widen the tier intervals. The two tiers are sampled at
different fractions (100 of 13722 against 50 of 1915), so the **overall**
figure is weighted back to the population.

**Seed and determinism.** Seed `20261011`. Each stratum gets
`random.Random(f"{seed}|{stratum}")`. The data is pinned by
`data_incidents_sha256` in `frame.json` (it was drawn from main `6da13032`).
`python scripts/precision_sample.py --check` re-derives every generated file
in memory and compares it byte-for-byte. With `--seed 7` it reports "NOT
reproduced", and none of its 150 ids overlap with this sample.

**Raw text.** Descriptions are not copied into this directory. A reviewer
opens the row by id in `data/incidents.json`. There are three reasons:
invariant 7 is advisory for new work (WS3-T6 is not done), the DATASHEET
warns that free text can carry payloads, and OECD/AIAAIC narrative text has
its own licence constraints (E21).

**Estimator.** `scripts/wilson_ci.py` uses the stratified estimator
`p = Σ (N_h/N)(x_h/n_h)` with a Wilson score 95% interval at Kish's effective
n. It is unit-tested against Newcombe (1998), Table I. There are two
treatments of `unsure`: excluded, and strict (unsure counts as out). Strata
with no counted rows are reported as `unrepresented_population` and never
imputed.

## What the user does with the sheet

1. Open `review_sheet.csv`. For each row, read the row in `data/incidents.json`
   (`pointer` column) and its references, and judge it against INCLUSION.md.
2. Fill **`human_label`** with exactly one of `in-scope`, `out-of-scope` or
   `unsure`, **`human_by`** with your name or handle, and optionally
   `human_note`. A label without `human_by` is refused. A `human_by` that
   names an agent or model (agent, Claude, GPT, LLM, AI, bot, …) is refused.
   The `suggested_*` columns are never read.
3. Do not reorder, add or delete rows (the gate checks the ids against the
   sample).
4. Commit the sheet, then run
   `python scripts/wilson_ci.py --render-datasheet` and commit `results.json`
   and `docs/DATASHEET.md`. A partly filled sheet renders as "partial", and no
   figure is published until all 150 rows are labelled.
5. Until then, one decision belongs to the user: whether to **ratify the
   pending state**. To ratify, put your decision id and date into
   `pending_authorization.json` and set the same id in
   `REQUIRED_PRECISION_PENDING_DECISION` in `scripts/validate.py`. Without
   that, validate passes the pending state with a warning only through
   dataset version 2.13.x, and fails it from 2.14.0.

## How `scripts/ai_relevance.py` will be evaluated (after the sheet returns)

`python scripts/evaluate_ai_relevance.py` exits 3 with "no human labels"
today. Once labels exist, it scores `ai_relevance.assess()` on the sampled
`*/cve-ghsa` rows, the only rows in that filter's domain. Positive means human
`in-scope`; `unsure` rows are excluded and counted. The output is a confusion
matrix (TP/FP/FN/TN), the filter's precision and recall with Wilson
intervals, and the list of disagreements. **Known approximation:** at ingest,
`assess()` also sees the CVE record's vendor/product/package fields and the
assigning CNA. The corpus row keeps only `affected`, so the Linux-CNA rule
cannot fire. For an exact replay, re-run `assess()` on the cached cvelistV5
records.

## The validate.py gate

*Superseded in part by the BOUNCE #1 update below; this list is kept as originally written.*

`scripts/validate.py::check_precision_audit` checks five things:

- **(a)** the sample is untampered: the entries hash to their declared hash,
  and the sheet ids match the sample ids in order;
- **(b)** `results.json` equals a fresh computation from the human columns;
- **(c)** the DATASHEET block equals the rendering of `results.json`;
- **(d)** while the status is not `measured`, the pending state carries a
  D28-form marker: `decided_by: "user"`, and an `entries_sha256` equal both to
  the sample and to the value pinned in code;
- **(e)** a placeholder decision id is tolerated, with a warning, only
  through dataset version 2.13.x.

There is no precision floor. Whether to impose one, and at what level, is a
policy decision for the user once a measured figure exists.

## Update 2026-10-11 (BOUNCE #1): what changed

A red-reviewer gate found that the code pin in item **(d)** above ran only
while the audit was pending. In the measured state, the only state that
publishes a figure, three bypasses passed: a swapped sample id with its hash
recomputed, an edited `frame.json` population (an estimator weight), and a
newer self-consistent dated directory. The gate now enforces these in
**every** status:

- the audit directory is pinned (`PRECISION_AUDIT_DIR_REL`), and any other
  dated directory under `docs/audits/precision/` fails;
- the sample's entries hash must equal `REQUIRED_PRECISION_SAMPLE_ENTRIES_SHA256`;
- the canonical hash of the whole `frame.json` must equal
  `REQUIRED_PRECISION_FRAME_SHA256`.

The pending-state marker check is otherwise unchanged. Fire tests for each
bypass run in the measured state (`tests/test_precision_audit.py`).

Two other changes:

- **Per-`quality_tier` figures** (the claim above) are now produced:
  `results.json` carries `by_quality_tier` for each tier. These are domain
  estimates in ratio form, flagged `small_n` below 30 rows, and should be read
  as indicative.
- **Editing the sheet in Excel or another spreadsheet.** Saving can add a
  byte-order mark, switch to CRLF line endings, re-quote every field, or (in
  some locales) change the delimiter to a semicolon. The loader tolerates the
  first three. It refuses a sheet whose `id`/`human_label`/`human_by` columns
  it cannot find, rather than miscounting. Safest: edit in a plain-text
  editor, or save as "CSV UTF-8 (comma delimited)" and keep the header
  unchanged.
